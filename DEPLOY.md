# Выкатка InsurWP

Проект состоит из двух независимых частей на одном сервере:

| Часть | Где живёт | Что это |
|---|---|---|
| Плагин WordPress | `bginfo.eu`, `wp-content/plugins/insurwp/` | PHP-код: калькулятор, REST API, админка |
| Telegram Mini App | `miniapp.bginfo.eu`, корень домена | Статическая сборка React (`miniapp/dist/`) |

Доступ к серверу — **только FTP или файловый менеджер панели хостинга** (cPanel,
ISPmanager, FASTPANEL и т.п.), SSH нет. Все шаги ниже рассчитаны на это: сборка
делается локально, на сервер заливаются уже готовые файлы.

Если у панели хостинга есть загрузка ZIP с распаковкой на сервере («Upload» +
«Extract» в файловом менеджере) — используйте её, это сильно быстрее, чем
закачивать файлы по одному через FTP-клиент.

---

## 1. Плагин: первая установка

1. Собрать архив локально:

   ```powershell
   cd D:\1PythonProjects\20260729PlaginWP\insurwp
   .\build-plugin.ps1
   ```

   Результат — `build/insurwp-<версия>.zip`. Скрипт берёт версию из `insurwp.php`
   и кладёт в архив только рантайм-файлы: `insurwp.php`, `includes/`, `assets/`,
   `data/`, `readme.txt`. Каталоги `tests/`, `miniapp/`, `composer.json` и прочее
   для разработки в архив не попадают.

2. Проще всего — через саму админку WordPress, файловый доступ не нужен:
   **Плагины → Добавить новый → Загрузить плагин** → выбрать
   `insurwp-<версия>.zip` → **Установить** → **Активировать**.

3. Если загрузка через админку недоступна (лимит на размер файла, ограничения
   хостинга) — через FTP/файловый менеджер:
   - распаковать `insurwp-<версия>.zip` локально — получится папка `insurwp/`;
   - загрузить её целиком в `wp-content/plugins/` (или загрузить сам ZIP через
     файловый менеджер хостинга и распаковать уже на сервере);
   - зайти в **Плагины** в админке и активировать «InsurWP».

4. Проверить и настроить: **Страховка → Настройки**.
   - «Страница оформления» — куда ведёт кнопка «Заказать», по умолчанию
     `https://bginfo.eu/insur/`.
   - «Адреса мини-аппа» — по умолчанию уже `https://miniapp.bginfo.eu`, менять
     не нужно, если домен мини-аппа не менялся.
   - Остальные поля (курс валюты, agent_id, гражданство по умолчанию) — по
     необходимости.

5. Вкладка **Страховка → Подключение** — один раз добавить сниппет
   `bginfo-prefill.js` на страницу оформления (`bginfo.eu/insur/`), см. раздел
   README «Автозаполнение на странице оформления». Без этого шага кнопка
   «Заказать» работает, но поля на странице оформления не заполняются
   автоматически.

## 2. Плагин: обновление

При обновлении **не удалять плагин через админку** («Деактивировать» → «Удалить»)
— так проще всего случайно стереть тарифы и настройки, если в будущем в плагине
появится `uninstall.php`. Правильный путь — просто перезаписать файлы.

1. Локально:

   ```powershell
   cd D:\1PythonProjects\20260729PlaginWP\insurwp
   .\build-plugin.ps1
   ```

2. **Если меняются PHP-файлы, но не CSS/JS** — версию можно не трогать.
   **Если меняются `assets/css/*` или `assets/js/*`** — обязательно поднять
   версию перед сборкой, иначе браузеры и кэширующие прокси отдадут
   пользователям старые файлы из кэша:

   - `insurwp.php`, строка `* Version:           1.0.0` — новая версия;
   - `insurwp.php`, строка `define( 'INSURWP_VERSION', '1.0.0' );` — то же
     значение. Обе строки должны совпадать.

   Пересобрать архив после правки версии.

3. Распаковать `insurwp-<версия>.zip` локально, залить содержимое папки
   `insurwp/` в `wp-content/plugins/insurwp/` на сервере **поверх существующих
   файлов** (FTP-клиент или файловый менеджер хостинга — с подтверждением
   перезаписи). Плагин деактивировать не нужно, сайт при этом не падает.

4. Если в обновлении появились новые файлы (например, новый класс в
   `includes/`) — залить их отдельно, обычная перезапись существующих их не
   создаст.

5. Настройки и тарифы не теряются: они хранятся в базе данных WordPress
   (`wp_options`), а не в файлах плагина. Новые настройки (например, добавленное
   позже поле) автоматически получают значение по умолчанию — ничего вручную
   пересохранять не нужно.

## 3. Мини-апп: первая установка

⚠️ На `miniapp.bginfo.eu` сейчас лежит другое работающее приложение
(путеводитель по Болгарии) — оно будет полностью заменено калькулятором.
**Обязательно сделать резервную копию перед заливкой** (шаг 2).

1. Локально собрать статику:

   ```powershell
   cd D:\1PythonProjects\20260729PlaginWP\insurwp\miniapp
   ```

   В `.env` должно быть:

   ```
   VITE_INSURWP_API_BASE=https://bginfo.eu/wp-json/insurwp/v1
   ```

   Затем:

   ```powershell
   npm ci
   npm run build
   ```

   Результат — папка `miniapp/dist/` (`index.html` + `assets/`).

2. Резервная копия: через файловый менеджер хостинга открыть корень
   `miniapp.bginfo.eu` (в панели он может называться `Domains` /
   `Subdomains` — найти документ-рут для `miniapp.bginfo.eu`), выделить всё
   содержимое и заархивировать функцией панели («Compress» / «Архивировать»)
   в файл вида `_backup_guide_2026-09-15.zip`. Оставить архив рядом, не в
   веб-корне, где его можно случайно перезаписать.

3. Удалить из корня `miniapp.bginfo.eu` всё содержимое старого приложения.

4. Загрузить в этот же корень содержимое `miniapp/dist/` **целиком**
   (`index.html` и папку `assets/` — не саму папку `dist`, а то, что внутри неё).

5. Проверить: открыть `https://miniapp.bginfo.eu/` в браузере — должна
   загрузиться форма калькулятора. Открыть в Telegram через BotFather-ссылку
   (адрес не менялся, перенастраивать бота не нужно).

## 4. Мини-апп: обновление

Мини-апп — статика без сервера: каждое обновление — это просто полная замена
содержимого корня свежей сборкой. Смешивать старые и новые файлы не стоит —
Vite даёт файлам в `assets/` новые имена с хэшем при каждой сборке, старые
неиспользуемые файлы иначе будут копиться на сервере.

1. Локально:

   ```powershell
   cd D:\1PythonProjects\20260729PlaginWP\insurwp\miniapp
   npm run build
   ```

2. В корне `miniapp.bginfo.eu`: удалить `index.html` и папку `assets/`
   целиком, загрузить новые `index.html` и `assets/` из `miniapp/dist/`.

3. Кэш: `index.html` браузеры и CDN обычно не кэшируют долго, а файлы в
   `assets/` — с хэшем в имени, поэтому старая версия сайта никогда не
   «подмешается» к новой. Если на хостинге настроен CDN/прокси-кэш —
   после заливки стоит сбросить кэш именно для `https://miniapp.bginfo.eu/`
   (без хвоста `/assets/...`).

## 5. Проверка после любой выкатки

Выполняется локально, доступ к серверу не нужен:

```powershell
# Плагин отвечает и знает о мини-аппе
curl.exe -s https://bginfo.eu/wp-json/insurwp/v1/options | Select-Object -First 1

# CORS для мини-аппа настроен: один Access-Control-Allow-Origin, без Allow-Credentials
curl.exe -i -X OPTIONS -H "Origin: https://miniapp.bginfo.eu" `
  -H "Access-Control-Request-Method: POST" `
  https://bginfo.eu/wp-json/insurwp/v1/quote

# Мини-апп отдаётся
curl.exe -s -o $null -w "%{http_code}`n" https://miniapp.bginfo.eu/
```

Плюс глазами: открыть калькулятор на сайте (шорткод), открыть
`https://miniapp.bginfo.eu/`, пройти форму до конца и нажать «Заказать» —
должна открыться `bginfo.eu/insur/` с уже заполненными полями.

## 6. Откат

**Плагин.** Хранить предыдущий `build/insurwp-<версия>.zip` до тех пор, пока
новая версия не проверена на проде. Откат — та же процедура обновления
(раздел 2), только исходник — распакованный архив старой версии.

**Мини-апп.** Восстановить содержимое корня `miniapp.bginfo.eu` из архива
`_backup_*.zip`, снятого при установке (раздел 3, шаг 2), либо из локальной
папки `miniapp/dist/` от предыдущей сборки, если она сохранилась.

## 7. Частые проблемы

- **WP admin пишет «Destination folder already exists» при загрузке ZIP
  обновления.** Так и должно быть — админка не умеет обновлять плагин поверх
  существующего простой загрузкой ZIP. Для обновления используется не
  загрузка через админку, а перезапись файлов через FTP/файловый менеджер
  (раздел 2).
- **После обновления CSS/JS в браузере старый вид.** Забыли поднять
  `INSURWP_VERSION` перед сборкой — см. раздел 2, шаг 2. Жёсткая перезагрузка
  страницы (Ctrl+F5) это не чинит для других посетителей, только версия
  в коде.
- **Мини-апп не может получить данные, в консоли браузера ошибка CORS.**
  Проверить в **Страховка → Настройки → Адреса мини-аппа**, что там указан
  ровно `https://miniapp.bginfo.eu` (без пробелов и хвостового слэша), и
  прогнать команду из раздела 5 — должен быть один заголовок
  `Access-Control-Allow-Origin`.
- **Кнопка «Заказать» открывает страницу оформления, но поля пустые.**
  Проверить, что на `bginfo.eu/insur/` подключён `bginfo-prefill.js` (раздел 1,
  шаг 5) — без него автозаполнение не работает независимо от того, из сайта
  или из мини-аппа открыта ссылка.
- **После обновления мини-аппа в самом Telegram всё ещё старая версия, хотя
  `curl https://miniapp.bginfo.eu/` уже отдаёт новый `index.html` и новые файлы
  в `assets/`.** Это не проблема выкатки — Telegram кэширует мини-апп на
  стороне клиента отдельно от обычного HTTP-кэша браузера. Сначала проверить
  сервер через `curl` (раздел 5) — если там всё новое, значит дело только
  в клиенте:
  1. Полностью закрыть Telegram (завершить процесс, не просто свернуть) и
     открыть заново — обычно достаточно этого.
  2. На телефоне: **Настройки Telegram → Данные и память → Очистить кэш**
     (кэш самого Telegram, не браузера).
  3. Если не помогло: в BotFather (`/myapps` → бот → Edit Web App) переуказать
     тот же URL мини-аппа с добавленным параметром, например
     `https://miniapp.bginfo.eu/?v=2` — Telegram кэширует по полному URL,
     новый параметр заставит перекачать всё заново. Домен и остальные
     настройки бота не меняются, само приложение параметр игнорирует.
